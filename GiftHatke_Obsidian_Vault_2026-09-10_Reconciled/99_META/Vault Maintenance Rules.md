# Vault Maintenance Rules

1. Preserve certified history; never silently overwrite it.
2. Put exact Git hashes, tags, deployment versions and SHA-256 evidence in registers.
3. Use ISO dates (`YYYY-MM-DD`).
4. Separate **business canon** from **runtime implementation**.
5. Separate **current production** from **planned roadmap**.
6. Every new major decision gets:
   - a decision-register entry,
   - a link to affected domain/module,
   - owner/status/evidence where known.
7. Every incident gets an incident note and links to the corrective commit/certification.
8. Every SOP should explain **how + why**, using real Gift Hatke workflows.
9. Customer images/names/messages used for customized products must not be retained in reusable public listing artwork; use clean placeholders.
10. Before declaring a scope certified, reconcile the vault with repository certification evidence.
